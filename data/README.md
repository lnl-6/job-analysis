# data/ —— 数据目录说明

## 目录约定

```
data/
└── raw/
    ├── 大学生就业数据.csv          # 真实数据（若有；**默认不入库**）
    ├── demo_大学生就业数据.csv     # 合成演示数据（仓库自带，可直接跑）
    ├── boss_岗位数据集.csv         # Boss 岗位适配后的分析数据集（本地生成，**默认不入库**）
    ├── boss/                       # Boss 抓取的原始 JSONL（本地生成，**默认不入库**）
    └── sample/                     # Boss 岗位手工样例（29 行，入库，供离线跑通与测试）
```

> **真实数据只留在本地**：`data/raw/大学生就业数据.csv` 已写进 `.gitignore`，
> 提交与推送都不会带上它（它属于他人的调查数据，未经许可不应再分发）。
> 仓库里带的永远是 `demo_` 开头的合成数据，因此任何拿到仓库的人都能直接跑通全流程。

## 数据来源（使用真实数据时必须登记）

> ℹ️ **本仓库只自带合成演示数据**（`demo_大学生就业数据.csv`），所以本节默认是一份空模板。
> 一旦放入真实数据，请把下面几项补全——没有来源标注的数据，结论不可信、也不可被引用：
> - 来源：XX 高校就业指导中心 2025 届毕业生就业质量调查
> - 样本量：N 条
> - 采集时间：2025-06
> - 是否已脱敏：是（姓名/学号已移除）

## 字段说明

| 字段 | 必需 | 类型 | 说明 | 允许值 |
|---|---|---|---|---|
| 学历 | ✅ | 分类 | 最高学历 | 本科 / 硕士 / 博士 |
| 专业 | ✅ | 分类 | 所学专业 | 自由文本 |
| 期望薪资 | ✅ | 数值 | 毕业后期望月薪（元） | > 0（非正值视为无效记录，清洗时剔除） |
| 满意度评分 | ✅ | 数值 | 就业满意度 | 0 – 5 |
| 是否有实习经历 | ✅ | 分类 | 在校期间是否有实习 | 是 / 否 |
| 毕业去向 | ✅ | 分类 | 毕业后的去向 | 就业 / 考研 / 出国 / 创业 / 待业 |
| 工作城市 | ✅ | 分类 | 期望工作城市 | 城市名 / 无 / 其他 |
| 性别 | ❌ 可选 | — | **本项目不做性别维度分析**，有这一列也不影响；没有也能跑 | 任意 |

> 列名必须与上表**完全一致**（包括空格和标点）。
> 放好数据后先跑 `python main.py --check-data` 验证列名和类型。

## 数据加载顺序

`src/loader.py` 的加载顺序：

1. `data/raw/大学生就业数据.csv` —— **真实数据，优先加载**
2. `data/raw/demo_大学生就业数据.csv` —— 演示数据，兜底

若使用演示数据，程序会在控制台和报告中**显著标注**，避免把演示结论当成真实结论。

## 手动放入真实数据的步骤

1. 把 CSV 改名为 `大学生就业数据.csv`
2. 放到 `data/raw/` 目录下
3. 运行 `python main.py --check-data` 确认列名和类型没问题
4. 运行 `python main.py` 出报告

## 关于 demo 数据

`demo_大学生就业数据.csv` 由 `scripts/generate_demo_data.py` **合成生成**（固定随机种子，可复现）。

- 用途：让仓库 clone 下来即可运行，无需真实数据
- **它不是真实数据**，所有结论仅用于演示代码流程，**不得用于任何真实结论引用**
- 重新生成：`python scripts/generate_demo_data.py`（默认 `--scenario effects --seed 42`，与仓库自带文件一致）

### 演示数据的模拟场景（全部参数公开）

这些参数是**数据说明**，不是分析结论。程序不会把参数表当成结果输出：报告里的均值、差值、
置信区间、p 值与判定，全部由 `src/stats.py` 在运行时从数据算出（README 也不复述任何具体数字）。

| 参数 | effects（默认） | null（校准对照） |
|---|---|---|
| 学历基准薪资 | 本科 6000 / 硕士 8500 / 博士 12000 | 三者都是 6000（无差异） |
| 学历抽样比例 | 本科 70% / 硕士 25% / 博士 5% | 同左 |
| 城市系数 | 上海·北京·深圳 1.25｜广州 1.15｜杭州 1.10｜南京·武汉·成都 0.95｜其他 0.80｜无 0.90 | 全部 1.0 |
| 专业系数 | 计算机 1.30｜电子信息 1.20｜临床医学 1.15｜金融 1.10｜数学 1.00｜机械 0.95｜法学 0.95｜土木工程 0.90｜英语 0.85｜市场营销 0.85 | 全部 1.0 |
| 实习乘数 | 是 1.08 / 否 1.0 | 都是 1.0 |
| 去向乘数 | 就业 1.0｜考研 0.90｜出国 1.0｜创业 1.0｜待业 0.80 | 全部 1.0 |
| 个人浮动 | 基准 × U(0.85, 1.15) | 同左 |
| 满意度构造 | 2.6 + 薪资分位×1.4，再按实习/去向微调，加 N(0, 0.35) | 3.2 + N(0, 0.8)（与分组无关） |
| 注入缺失 | 性别 4% / 期望薪资 5% / 实习经历 3% | 同左 |
| 注入异常值 | 2% 的行 × U(3.0, 4.5) | 同左 |

核对方式（参数表直接来自脚本，可随时复核）：

```bash
python scripts/generate_demo_data.py --show-params
python scripts/generate_demo_data.py --show-params --scenario null
```

`null` 场景的用途是**校准**：它按定义不含任何分组差异。如果分析管线在这个场景上报出
「差异显著」，说明检验存在假阳性问题。CI 会跑这个场景（见 `.github/workflows/ci.yml`）。

### 本仓库对「结果」的态度

- 程序内不存放任何预设结论或预测；报告里每个数字都来自当次运行，并带数据指纹与参数记录。
- README 不复述任何一次运行的具体数字（有测试守着），避免出现与数据脱钩的「预设结论」。
- 样本量低于 `config.MIN_GROUP_SIZE`（默认 30）的分组不给差异结论；交叉分析中样本不足的组合直接留空。

## Boss 直聘岗位数据（另一个数据源）

`src/sources/boss.py` 把 Boss 直聘的岗位 JSON 适配成**同一套 7 列分析契约**，所以清洗 / 统计 / 体检 / 报告全部复用，只是口径不同：

| 契约列 | 问卷数据 | 岗位数据 |
|---|---|---|
| `学历` | 受访者学历 | 岗位要求的学历（不限 → `不限`） |
| `专业` | 所学专业 | 岗位方向（数据分析 / 数据开发 / 算法 / 数据治理 / 数据产品 / 其他） |
| `期望薪资` | 受访者期望月薪 | 岗位薪资区间中值（元/月）；`面议` 留空后按中位数填充并留痕 |
| `满意度评分` | 受访者满意度 | 岗位吸引力**代理分**（0~5，不是满意度） |
| `是否有实习经历` | 在校是否实习过 | 岗位是否面向实习/应届 |
| `毕业去向` | 就业/考研/出国/创业/待业 | 岗位类型（实习/校招/社招） |
| `工作城市` | 期望工作城市 | 岗位工作城市（空值 → `无`，统计时按占位值排除） |

- **离线跑通（不联网）**：用仓库自带的手工样例

  ```bash
  python -m src.sources.boss --raw data/raw/sample/boss_jobs_sample.jsonl \
      --out "data/raw/boss_岗位数据集.csv"
  python main.py --data "data/raw/boss_岗位数据集.csv"
  python tests/test_source_boss.py      # 10 项离线测试
  ```

- **真实抓取**：`$env:BOSS_COOKIE="..."` 后跑 `python scripts/crawl_boss.py --query 数据分析 --city 北京`
  （低频、礼敬、断点续爬；抓取产物与生成的数据集默认不入库）
- **样本来源必须登记**：真实抓取的数据属于站点内容，发布仓库时只提交 `sample/` 下的手工样例；
  若确实基于真实抓取结果下结论，请在报告的数据来源里注明采集时间、关键词、城市与页数。
- 口径细节（薪资解析、代理分公式、合规边界、已知限制）见 [`docs/data_source_boss.md`](../docs/data_source_boss.md)。
